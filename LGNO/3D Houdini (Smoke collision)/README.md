# 3D Houdini smoke collision

## 1. Problem

This case learns the velocity update of a three-dimensional smoke-collision
trajectory exported from SideFX Houdini.

The update is:

$$
\mathbf{v}_{t+1}
= \mathbf{v}_t
+ \Delta\mathbf{v}_{\mathrm{local}}
- \Delta t_{\mathrm{eff}}\nabla p_t.
$$

LGNO predicts only the local pressure-free update:

$$
\Delta\mathbf{v}_{\mathrm{local}}
\approx
\Delta t_{\mathrm{eff}}
\left[
-(\mathbf{v}\cdot\nabla)\mathbf{v}
+\nu\Delta\mathbf{v}
+\text{local numerical effects}
\right].
$$

The pressure gradient is computed from the saved pressure field and applied
outside the neural network.

## 3. Data preparation

Create the following directory inside this case folder:

```text
bunny_teapot_collision_128x128x128_open/
├── metadata.json
└── fields/
    ├── frame_0000.npz
    ├── frame_0001.npz
    ├── frame_0002.npz
    └── ...
```

Each `frame_*.npz` file must contain:

```text
u, v, w, p
```

Optional but recommended fields:

```text
time, step
```

The grid used in the recorded experiment was 128×128×128. The complete source
dataset was approximately 33.6 GB.

`metadata.json` must provide the simulation quantities read by the script,
including:

```text
dt
nu
Lx
Ly
Lz
```

If frame times are available, the effective learning time step is inferred
from them. Otherwise, it is inferred from the solver time step and saved step
stride.

## 4. Model

The model is a component-shared scalar LGNO.

For every transition, each velocity component becomes one scalar training
sample:

```text
main input:
    scalar seven-point stencil of the selected component

auxiliary input:
    center velocity (u,v,w)
    center speed

target:
    pressure-free local update of the selected component
```

Each physical transition therefore supplies three scalar samples.

The seven-point stencil is:

```text
center, -x, +x, -y, +y, -z, +z
```

Open boundaries use replicate padding. This case does not use periodic rolling.

## 5. Training configuration

The preserved implementation uses the following direct configuration:

| Item | Value |
|---|---:|
| Data directory | `bunny_teapot_collision_128x128x128_open` |
| Training transitions | 100 |
| Rollout steps | 100 |
| Hidden dimension | 16 |
| Epochs | 800 |
| Batch size | 1 |
| Initial learning rate | 2e-3 |
| Weight decay | 1e-6 |
| Early-stopping patience | 120 |
| LR factor | 0.5 |
| LR scheduler patience | 8 |
| LR threshold | 1e-5 |
| Minimum learning rate | 1e-6 |
| Chunk size | 32,768 voxels |
| Rollout clamp norm | 20 |
| Auxiliary speed | enabled |
| Seed | 42 |
| Saved rollout frames | 1–20 |

These values are defined at the top of `_lgno_impl.py`.

## 6. Run

From this case directory:

```bash
python LGNO.py
```

From the package root:

```bash
python run_lgno.py houdini-3d
```

The current numerical implementation uses direct configuration rather than
`argparse`. To change the data directory or training settings, edit the
configuration block at the top of `_lgno_impl.py`.

The model explicitly reports rollout metrics in `metrics.txt`; the exact keys
are generated by `compute_rollout_metrics` in `_lgno_impl.py`.

## 9. Expected behavior

- At least 101 frames are required for 100 training transitions.
- Every velocity and pressure array must use the same 128×128×128 grid.
- `dt_eff`, `dx`, `dy`, and `dz` must be finite and positive.
- The script should report 300 component-wise scalar training samples.
- Training loss and rollout tensors must remain finite.
- A successful run ends with `All results saved successfully.`
